# DeepSneak 观看历史设计

日期：2026-08-17

## 背景

当前工作区已经在 `lib/client.js` 和 `src/dynamic/client.js` 中加入了观看历史的初版：本地持久化、历史 Tab、最多 50 条记录、进度保存和从历史恢复。本阶段先沿用仓库现有的无构建双文件模式，把这部分行为补齐并稳定下来。

共享模块和新的构建流程属于后续独立阶段，不纳入本次实现。

## 目标

用户可以：

1. 在“观看历史”Tab 中看到最近观看的视频。
2. 重新打开视频时从上次未完成的位置继续播放。
3. 播放完成后再次打开时从头播放。
4. 清空全部观看历史。

历史数据只保存在当前浏览器的 `localStorage` 中，不新增服务端接口或远程存储。

## 数据模型

存储键为 `deep-sneak.history.v1`，值为数组。每条记录包含：

```js
{
  bvid: string,
  title: string,
  pic: string,
  up: string,
  duration: string | null,
  watchedAt: number,
  progress: number
}
```

约束：

- 数组按最近观看时间倒序排列，最多保留 50 条。
- `bvid` 是去重键；同一视频再次打开时更新元数据并置顶。
- `progress` 为非负整数秒数；无有效进度时为 0。
- 读取数据时过滤非法条目，避免损坏的 localStorage 让组件崩溃。
- 当前版本不迁移旧的观看历史键；统计数据的既有迁移逻辑保持不变。

## 播放生命周期

### 创建或更新记录

视频详情和播放地址加载成功后，执行历史记录 upsert。若已有同一 `bvid` 的记录，保留已有进度，除非本次播放明确来自“播放完成后的重置”。随后更新标题、封面、UP 主、总时长和 `watchedAt`，并把记录放到数组首位。

### 保存进度

当前视频的播放进度在以下时机保存：

- 播放过程中每 30 秒定时落盘。
- 用户暂停视频时。
- 切换视频时。
- 页面 `beforeunload` 和组件卸载时。

保存时取 `Math.floor(video.currentTime)`，并限制为不小于 0 的数值。

### 恢复进度

从历史卡片打开时把记录进度传给播放器。`loadedmetadata` 后，仅当进度大于 0 且没有接近视频结尾时设置 `currentTime`；播放完成记录按 0 秒处理，因此下一次从头播放。

### 播放完成

`ended` 事件先结算摸鱼统计，再将当前历史记录的进度重置为 0 并更新时间。历史记录保留，仍然置顶；卡片重新显示视频总时长而不是旧进度。

## UI 行为

- feed、search 和 history 三类卡片共用渲染逻辑。
- 历史卡片显示最近观看时间。
- `progress > 0` 时显示已保存进度，否则显示总时长。
- 历史为空时显示空状态文案。
- 历史 Tab 提供“清空历史”按钮，清空后同步更新 React 状态和 localStorage。

## 实现边界

本阶段只修改：

- `lib/client.js`：发布版浏览器 bundle。
- `src/dynamic/client.js`：动态插件原型，保持行为同步。
- 必要的测试文件和 README 路线图说明。

不修改 Host API、不增加依赖、不引入构建工具、不重构两份客户端的共同代码。

## 测试与验证

使用 Node 内置 `node:test` 覆盖以下纯行为：

- 非法历史数据被过滤。
- 同一视频 upsert 后去重并置顶，同时保留进度。
- 历史数量上限为 50 条。
- 播放完成会把进度归零。
- 恢复进度不会超过视频结尾。

实现完成后运行：

- 历史行为测试。
- `lib/index.js` 和 `lib/client.js` 语法检查。
- 动态源码语法检查。
- Host 路由注册 smoke test。
- `npm pack --dry-run`，确认发布包内容和入口没有变化。
- `git diff --check`。
